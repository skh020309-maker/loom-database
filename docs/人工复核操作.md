# 人工复核操作

本工具让组员检查并修订摘要、分类和标签，保存每次操作的前后差异。原文、出处、作者与定位不被修改。当前候选标注均未由真人确认；提供工具不等于已经完成人工复核。

## 查看一条记录

在仓库根目录执行：

```powershell
python scripts/review_notes.py show pub-001
```

先查看 `original_excerpt`、`url`、`excerpt_locator` 和 `annotation`，需要上下文时打开原页。

## 修改候选标注

下面是命令格式示例，仅在实际审阅后执行。`--tag` 可以重复；提供标签时替换这条笔记的整组标签。未提供的摘要、分类和标签会保留原值。

```powershell
python scripts/review_notes.py update pub-001 --origin human --actor reviewer-A --reason "核对原页后调整中文措辞" --status pending --summary "每条笔记围绕一个完整概念，有助于建立跨主题联系。" --category idea --tag 常青笔记 --tag 知识连接
```

人工确认当前结果无需再改：

```powershell
python scripts/review_notes.py update pub-001 --origin human --actor reviewer-A --reason "已核对摘录、上下文、摘要和分类" --status verified
```

发现不适合使用但需要保留审计记录时，使用 `--status rejected`。待复核的 AI 建议只能使用 `--origin ai_assisted --status pending`，不能冒充人工确认。

`--actor` 填实际操作者的组内代号即可。仓库公开，避免在日志里写入学号、联系方式或私人信息。工具不验证操作者身份，它是课程小组本地工作工具，不是产品登录系统。

## 修改后刷新导出

```powershell
python scripts/manage.py check
python scripts/manage.py export --format json
python scripts/manage.py export --format csv
python scripts/manage.py export --format markdown
python scripts/build_viewer.py
python scripts/export_mysql.py
```

浏览页可以按“复核状态”筛选。重新导入已有原始数据不会覆盖人工修改。

所有修订写入 `processing_logs`，包含操作者、原因、修改前后结果。复核不执行 GLM，也不改变训练许可。若同一状态和内容完全不变，重复执行不会增加重复日志。

复核记录保存在数据库及 MySQL 导出中；只拿原始采集 JSON 重建库无法恢复后来的人工修订，应同时备份 `loom.db`。
