# 人工复核操作

本工具让组员检查并修订摘要、分类和标签，保存每次操作的前后差异。原文、出处、作者与定位不被修改。当前候选标注均未由真人确认；提供工具不等于已经完成人工复核。

## 查看一条记录

在仓库根目录执行：

```powershell
python scripts/review_notes.py show pub-001
```

先查看 `original_excerpt`、`url`、`excerpt_locator` 和 `annotation`。原页可用于核对定位、作者与许可；短摘录摘要实验中的 `summary_zh` 只根据保存的 `original_excerpt`，不能把标题或原页其他段落补成摘要事实。当前类别、标签仍待同口径检查，不能直接视作仅由摘录支持的标准答案。

## 修改候选标注

下面是命令格式示例，仅在实际审阅后执行。`--tag` 可以重复；提供标签时替换这条笔记的整组标签。未提供的摘要、分类和标签会保留原值。

```powershell
python scripts/review_notes.py update pub-001 --origin human --actor reviewer-A --reason "依据保存的短摘录收窄中文措辞" --status pending --summary "作者说采用这种方式更容易建立跨主题和情境的联系；摘录未说明具体方式。"
```

人工确认当前结果无需再改：

```powershell
python scripts/review_notes.py update pub-001 --origin human --actor reviewer-A --reason "已核对摘录、上下文、摘要和分类" --status verified
```

发现不适合使用但需要保留审计记录时，使用 `--status rejected`。待复核的 AI 建议只能使用 `--origin ai_assisted --status pending`，不能冒充人工确认。

`--actor` 填实际操作者的组内代号即可。仓库公开，避免在日志里写入学号、联系方式或私人信息。工具不验证操作者身份，它是课程小组本地工作工具，不是产品登录系统。

## 修改后刷新导出

```powershell
python scripts/manage.py check
python scripts/manage.py export --format json
python scripts/manage.py export --format csv
python scripts/manage.py export --format markdown
python scripts/build_viewer.py
python scripts/export_mysql.py
```

浏览页可以按“复核状态”筛选。重新导入已有原始数据不会覆盖人工修改。

所有修订写入 `processing_logs`，包含操作者、原因、修改前后结果。复核不执行 GLM，也不改变训练许可。若同一状态和内容完全不变，重复执行不会增加重复日志。

复核记录保存在数据库及 MySQL 导出中；只拿原始采集 JSON 重建库无法恢复后来的人工修订，应同时备份 `loom.db`。

## 重放已复查的AI摘要修订

两份修订JSON均保留每条原文哈希、旧摘要、新摘要和修改理由：

- `data/annotation_revision_2026-10-21_zh.json`：中文21条，10月21日拟定与AI复查，10月22日实际应用。
- `data/annotation_revision_2026-10-22_en.json`：英文27条，10月22日范围检查、独立AI复查并实际应用。

两批共48条摘要变更，另2条保留；50条仍为AI辅助、待人工复核。先查看计划，再应用：

```powershell
python scripts/apply_annotation_revision.py data/annotation_revision_2026-10-21_zh.json --dry-run
python scripts/apply_annotation_revision.py data/annotation_revision_2026-10-21_zh.json
python scripts/apply_annotation_revision.py data/annotation_revision_2026-10-22_en.json --dry-run
python scripts/apply_annotation_revision.py data/annotation_revision_2026-10-22_en.json
```

该工具只处理AI辅助、待人工复核的摘要。每次执行（包括重放）时，已经由人工编辑或确认/驳回的目标记录会导致整批拒绝；原文哈希或旧摘要不一致也会整批回滚。所有校验通过后才整批提交，不留下半批已改的结果。

幂等识别使用修订内容的 canonical SHA-256，不受JSON缩进/排版、记录顺序和行尾形式影响；原文件的字节哈希另外保存，供核对实际输入文件。重放内容相同且已成功记录的修订会跳过，不重复写日志，也不覆盖随后完成的人工标注或把状态改回pending。实际修改写入`processing_logs`，保留哈希、修改理由与前后摘要。

从四个原始采集文件重建数据库后，按上面顺序重放中文、英文两份修订JSON，才能恢复这两批已应用摘要。原采集JSON仍保留采集时内容。未记录在修订文件中的后续人工工作仍须以`loom.db`及其审计日志备份恢复，不能只靠种子JSON和这两份AI修订重建。
