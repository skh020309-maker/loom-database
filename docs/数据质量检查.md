# Loom 数据质量检查

运行 `python scripts/audit_quality.py`，默认只读 `loom.db`，生成 `exports/data_quality.json`。可指定 `--db`、`--output`、`--threshold 0.65` 和 `--min-length 30`。仅使用 Python 标准库和现有 `manage.exported_records` 接口，不依赖额外来源核验表。

报告包含 `metrics`、`critical_issues`、`warnings`、`near_duplicate_candidates` 和按作者、完整 URL、源文档 URL 分组的记录 IDs。每次生成带 UTC 时间戳；同一数据库和参数得到相同业务统计。报告不改原文、人工标注、许可状态或任何数据库记录。

## 检查内容

- 原文精确重复、重复 ID、哈希不一致和字段契约错误：列出相关 IDs，属于阻止验收的问题。
- 规范化重复：只在比较键上做 NFKC、连续空白折叠、无歧义单反引号行内 code 标记剥离。保留 code 内文本，保留双/多反引号和转义反引号。比较键一致只列为待人工判定候选，不自动改写或删除原文。
- 近重复：规范化比较文本移除空白后，以字符 3-gram 集合计算 Jaccard。默认至少 30 个非空白字符、分数至少 0.65；已精确相同或规范化相同的文本不重复计入近重复候选。分数反映字面重叠，不能推断语义相同；短摘录排除 IDs 单独列出，避免少数字符造成无意义碰撞。
- 分组泄漏：作者名经 NFKC、空白和大小写归一；源文档 URL 去掉 `#fragment`，保留路径、查询参数、HTTP/HTTPS 差异。同作者或同源文档跨 dev/test 属于问题。完整 URL 对应不同作者也会列出。不会推断不同名字是否属于同一真人，也不会把不同查询参数自动合并。
- 覆盖与权利：统计原文字符长度、语言、分类、作者、来源、split、许可、摘要来源和复核状态；unknown 许可和 pending 标注列为警告。公开可访问不能自动得出训练许可。
- gold 口径：只有 `review_status=verified` 且填写核验者的记录才计入人工复核合格候选。AI 辅助且 pending 的摘要、分类和标签不计为 gold；即使已填写核验者，统计也不等于独立证明标签正确。
- 数据库完整性：SQLite integrity、外键、必需结构，以及来源或标注缺失导致 INNER JOIN 漏导出的记录均检查。连接使用 `mode=ro` 和 `query_only=ON`；缺库时不创建新库，输出路径不能覆盖数据库、硬链接或 WAL/SHM 文件。

## 结果解释

退出码 0 表示没有 `critical_issues`，仍可能有待人工复核、许可不明、短摘录或近重复候选警告。退出码非 0 表示存在 critical、数据库缺失、结构错误、路径错误或其他读取失败。可读但有 critical 的数据库仍会生成报告，便于保留问题 IDs；不能读取的库不会被当作空库报告成功。

这是一项离线结构与字面质量检查。它不访问原网页，不验证作者身份，不确认网页可用性或全文授权，也不表示已运行 MySQL、GLM 或语义检索。来源在线核验和人工标注复核须单独记录。

运行回归测试：`python -m unittest discover -s tests -p test_quality_audit.py -v`。
