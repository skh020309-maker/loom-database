# 来源核查记录

来源核查用于回答：原始 URL 此次能否读取、短摘录是否在原页出现、作者归属能否确认、作者是否明确声明再利用许可。它与中文摘要的语义复核是两件事。AI 辅助网页比对不构成人工语义金标准，不能把 `annotations.review_status=pending` 改成已人工确认，也不能据此声称已运行 GLM、获得训练许可。

## 记录如何保存

`source_checks` 按具体笔记摘录保存追加式记录，通过 `source_id` 与 `note_id` 同时关联来源和笔记；每次核查保留日期、核查者类型、抓取状态、摘录状态、作者状态、许可状态、许可证据 URL 和简短依据。原始 URL 在导入时必须已经存在；输入 `note_id` 必须属于该来源。输入省略 `note_id` 时，仅当该 URL 在库中恰好关联一条笔记才可唯一解析；关联零条或多条时拒绝导入，要求指定笔记。

导出保留单个 `note_id`、原始 URL 和作者。一条摘录比对成功不会传播到同 URL 的另一条摘录；之后从同页新采集的句子仍需独立核查。数据库联合外键约束笔记与来源必须匹配。

同 ID 且内容一致时重复导入会跳过；同 ID 的笔记、来源或核查内容改变会拒绝整批并回滚。新一轮核查请使用新 ID，保留旧记录。工具不修改来源表原始许可字段、原文、标签、人工标注或处理状态。

核查历史明确采用追加方式；数据库触发器拒绝对已有核查的 UPDATE 和 DELETE，工具也不会自动覆盖旧核查。后续结果发生变化时新增记录，并保留原来无法访问、存在差异或许可未确认的历史。

## 状态如何理解

- `accessible` 表示此次工具实际取得页面；`blocked` 或 `unavailable` 时，摘录和作者必须为 `not_checked`。无法取得正文不能当作摘录不存在，搜索摘要也不能代替原文。
- `exact` 为连续原文一致；`normalized_match` 只允许空白或行内代码等显示差异；`not_found` 只表示在已取得页面中未定位；`not_checked` 表示未能核对。
- 作者使用 `confirmed`、`conflict`、`not_checked`；许可使用 `confirmed`、`not_confirmed`、`conflict`、`not_checked`。许可确认或冲突必须给出有效证据 URL；许可未确认不表示没有版权。
- 许可证据应指向作者自己的声明位置或版权页。Creative Commons 官网只能解释条款，不能代替作者给该作品授权。相同作者不同作品也不能自动共享许可。

## 使用方法

在项目根目录运行，使用已有 Python 环境：

```powershell
python scripts/manage.py init
python scripts/source_audits.py import data/source_audit_2026-10-21_zh.json
python scripts/source_audits.py import data/source_audit_2026-10-21_en.json
python scripts/source_audits.py export --output exports/source_audit.json
python scripts/manage.py check
python -m unittest discover -s tests -p test_source_audits.py -v
```

指定其他数据库时把 `--db` 放在子命令前，例如 `python scripts/source_audits.py --db path/to/copy.db export --output path/to/checks.json`。导出不能覆盖数据库本身。原始人工审核入口继续使用现有标注流程，只有实际人工审阅后才能确认摘要。
