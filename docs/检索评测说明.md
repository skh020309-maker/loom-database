# Loom 检索验收候选基线

这套基线用于确认现有 SQL LIKE 检索实际能做什么，以及它在哪些自然表达上失败。它不是已完成的语义检索，也不是经过人工标注的正式测试集。

## 数据和标签

`data/retrieval_benchmark.json` 固定引用最初的 `pub-001` 至 `pub-022`，共 16 题：14 道候选正例、2 道候选无答案负例。题目覆盖中文自然表达、英文关键词和模糊回忆。每题的 `label_origin=ai_assisted`、`review_status=pending` 明确保留待人工复核状态。

正例的 `split` 继承目标笔记作者的分组；评测器拒绝不存在的目标 ID、固定参考集以外的目标、目标分组不一致，以及目标作者在数据库中跨 dev/test。负例没有目标作者，其 dev/test 只是题目分组。`ret-011` 有意使用含糊的 `SQLite` 查询，其他 SQLite 结果可能也相关，须人工检查候选目标是否完整。

参考题和目标 ID 不随扩库改写，但检索范围始终是当前数据库全部记录。扩库到 50 条后，新增候选可能影响排序和负例判断。结果保存题文件 SHA-256、全部可检索字段的语料 SHA-256、样本数量和执行时间；只有语料与题目版本一致时才适合直接比较。执行期间语料变化会导致评测失败，应在导入结束后重跑。

## 两条真实执行路径

1. **整句查询 `full_query`**：原封不动把 `query` 传入 `manage.search_database(db, query, limit=5)`。
2. **预指定关键词 `preset_keyword`**：把题目中已经固定的 `keyword_baseline` 传入同一函数，仍然是 SQL LIKE。

当前引擎在标题、原文、摘要、作者和标签中做字面匹配，按 ID 排序。它没有中文分词、自动关键词提取、语义向量或相关性重排序。英文关键词题两条路径可能相同，这是保留的直接可检索对照。预指定关键词是在阅读样本后选择的有利条件，用于诊断原始查询与索引文本之间的表达差异；其命中不能计为语义检索能力，也不能证明系统会自动提取同样的关键词。

## 指标口径

- **Hit@5**：仅对正例计算。前五条存在任一候选目标 ID 记 1，否则记 0，再取均值。
- **MRR@5**：仅对正例计算。第一个目标在第 r 位记 `1/r`，前五条没有目标记 0，再取均值。完全保留真实引擎返回次序，不重新排序。
- **负例错误返回率**：仅对无答案负例计算。有任何返回记 1，没有返回记 0，再取均值。它衡量检索返回，不衡量生成答案是否幻觉。

输出同时报告总体、dev/test 分组和查询类型分组结果、分母及每题详情。按查询类型分开查看，避免把英文关键词题的命中误读为中文整句理解。如果某分组没有正例或负例，对应指标输出 `null`，不会伪造为 0。空题集直接报错。候选标签可能漏标相关笔记，因此这些指标只是诊断读数，尚不能作为人工金标准准确率、正式验收通过率或对真实用户效果的估计。

## 运行

在 `loom-database` 目录中运行：

```powershell
python scripts/evaluate_retrieval.py
python scripts/evaluate_retrieval.py --db loom.db --benchmark data/retrieval_benchmark.json --output exports/retrieval_eval.json
python -m unittest discover -s tests -p test_retrieval_eval.py -v
```

默认读取 `loom.db` 和 `data/retrieval_benchmark.json`，输出 `exports/retrieval_eval.json`。脚本不调用 GLM、不访问网络、不修改数据库。非法题目、缺失目标或分组泄漏返回非零退出码。运行成功表示基线执行完成，不代表检索质量达标。

## 人工复核与后续比较

请逐题核对语义、目标列表和负例是否确实在全部语料中无答案，尤其是含糊查询的其他相关结果。保留当前候选基线及版本；人工确认后的正式评测集应另行版本化，并调整评测器对人工标签的接受规则。不要只通过修改题目来提高分数。

之后可在同一语料快照、同一题集上增加分词或真正的语义检索路径，再比较结果。该阶段未覆盖语音、OCR、真实学生输入、时间理解、LLM 回答质量或个人数据权限测试。
