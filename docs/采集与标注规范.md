# 采集与标注规范

## 收什么

优先个人公开笔记、数字花园、学习心得、研究问题和创意记录。研究论文是产品参考来源，不自动算作个人原始速记。首批使用短摘录，是为保证可核查和便于组员阅览。

内容角色必须区分：

| 类型 | 可以表示什么 | 不能表示什么 |
| --- | --- | --- |
| `public_excerpt` | 别人公开发表的笔记中的真实短片段 | 用户本人想法、完整原文、随机收集的真实学生速记 |
| `consented_original`（后续） | 经作者授权提交的原始记录 | 没有授权依据的同学聊天或日记 |
| `synthetic`（后续单独管理） | 专门设计的测试输入 | 真实人类调查或收集成果 |

当前仅支持公开样本的导入；新增其他类型时先扩展校验与授权字段，不混用现有类型。

## 每条必填

`id`、`title`、`author`、`url`、`source_kind`、`language`、`original_excerpt`、`excerpt_locator`、`summary_zh`、`tags`、`category`、`license_status`、`license_name`、`license_url`、`retrieved_on`、`evidence_note`、`split`、`content_origin`。

无法确认的许可写 `unknown`，许可名称与地址可为空；不能以“网页能打开”推断可以自由再分发。原文片段不超过 500 字符；首批英文片段每原始页面不超过 25 个词，不拼接不连续句子伪装连续原话。中文摘要写自己的概括，并保持简短。

`retrieved_on` 是实际核查日，不能替代作者发表时间。没有发表日期就不编日期。外部作者身份不应写入产品用户表或冒充当前用户。

## 如何标注

- `category` 使用 `question`（明确问题）、`idea`（建议或构想）、`note`（知识/经验记录）、`event`（真实事件记录）。
- 标签少而具体，建议 2–4 个；不要从作者未说出的动机推断标签。
- 中文摘要保留原文不确定性，避免把“可能”改成“必然”。
- 含相对时间时保留原话；缺少基准日期不自动生成提醒时间。
- 所有自动整理 `review_status=pending`；只有实际人工审阅后才可确认。
- `pipeline_status=not_run` 表示未通过 Loom 的 GLM 管线，不允许把数据准备过程充作该管线的成功日志。

## 去重和评测

原文按 Unicode 文本计算 SHA-256。相同内容不重复计数；同一 ID 的原文变动拒绝导入。近似重复另外人工检查，SHA-256 不能识别语义重复。

开发集/测试集按作者分组，不能随机逐行分割同一作者。公开整理好的笔记和学生的口语速记有明显差异，后续应用效果应单独用经授权的真实输入验证。

## 后续可直接发给组员的征集格式

这只是供组员使用的模板，未向任何人发送：

> 请自愿提供 3–5 条你自己写的学习笔记、问题或灵感，每条保留原始表述，去除姓名、学号、联系方式及他人隐私。说明是否同意仅在本小组课程演示和测试中使用，是否同意在仓库中保存，以及希望怎样署名。不愿提供不影响任何事宜。语音、手写图片需另外说明授权范围。

收到真实授权前，不把未提交的数据写入库。
