# Loom 数据库的高校项目参考

核查日期：2026-10-20（北京时间）。本页只使用大学官网、研究者原论文、项目官方代码仓库和作者发布的数据卡。以下是模块层面的相关研究，没有证据表明某所大学已经实现了与 Loom 完全一致的产品。

当前参考范围是：收集碎片笔记与想法、保留来源、辅助摘要与组织、检索后追问、由用户确认整理结果。论文里的效果不能直接当作 Loom 的效果；本项目仍需要用自己的样本检验。

## 对本周收集工作的具体建议

1. **分清采集对象。** 真实的他人笔记、本人撰写的来源摘要、人工构造的测试样本分开标识。不能把 AI 生成的“某人的笔记”计为真实采集量。
2. **优先保留出处。** 每条公开材料至少记录作者/机构、标题、原始链接、采集日期、材料类型、授权依据。没有明确许可的完整笔记先登记链接与简短自写摘要；不能因为能打开就默认可批量复制。
3. **先建小规模可检查的数据。** 包含短想法、待办、疑问、阅读摘记、多个主题混写、重复或近似笔记；主题不只覆盖计算机。先检查字段与流程，再逐日扩充。
4. **让 AI 结果可纠正。** 数据库同时保留原文、处理后的文本和摘要/分类建议；人工确认状态独立存储。每次修改保留时间与修改原因。
5. **以任务检验数据库。** 给样本编写自然表达的查找问题，例如“我之前记过哪个关于整理笔记的想法”，记录预期命中的笔记、遗漏和错误命中。把“资料已入库”和“自然语言检索已有效”分别验收。

这五条是由上述研究机制推导出的实施建议，不是论文已经验证过的 Loom 成效。第一周的重点是形成来源清楚、可查询、可持续扩充的数据库，而不是复现整套论文系统。
